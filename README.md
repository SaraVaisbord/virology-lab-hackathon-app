# אימות טפסי התחייבות – המעבדה המרכזית לנגיפים

מערכת שנבנתה בהאקתון של המעבדה המרכזית לנגיפים (המרכז הרפואי שיבא). היא קוראת טפסי התחייבות סרוקים, מחלצת מהם את השדות הנדרשים, מסמנת לבורנטית רק את מה שדורש החלטה, ומייצאת לאקסל **שורה לכל התחייבות**.

## מה המערכת עושה

1. **העלאה** – קובצי PDF או תמונות. כל עמוד נשמר כתמונה ומיושר (סיבוב והטיה) כבר בהעלאה.
2. **עיבוד מקדים** – הסרת סימון טוש צהוב, הפרדת שכבות דפוס / כתב יד / חותמות, ניקוי קווי טופס.
3. **קריאה משלושה מקורות נפרדים**
   - **ברקודים** (zbar)
   - **OCR מקומי** (Tesseract) – מוצא תוויות ("מספר התחייבות", "מרכזי", "התקבל"…) ואת הערך שלידן
   - **בינה מלאכותית** (Gemini) – אופציונלי, אפשר לכבות כדי לחסוך טוקנים
4. **הצלבה** – ערך מסומן "אומת" רק כשיש תווית שמוכיחה את השדה **וגם** שתי קריאות בלתי תלויות. כל השאר עובר ללבורנטית.
5. **מסך אימות** – הלבורנטית רואה את המסמך עם הערך מסומן עליו, את מה שכל מקור קרא, וכל מספר שנמצא בעמוד – ויכולה לבחור, לתקן, להוסיף או למחוק.
6. **ייצוא לאקסל** – שורה לכל מספר התחייבות; פרטי המטופל והדגימה חוזרים בכל שורה.

### שדות

| שדה | הערות |
|---|---|
| שם פרטי, שם משפחה, ת"ז | ת"ז נבדקת גם לפי ספרת ביקורת |
| מספר התחייבות | **המפתח של השורה**. מופיע גם כ"דרישה", וכ"דגימה" בטפסי לאומית ובטפסים שכתוב בהם שמספר הדגימה הוא מספר ההתחייבות |
| מספר מרכזי | המספר הפנימי שהמעבדה נותנת בקבלה (מדבקה "מרכזי"). יכולים להיות כמה |
| תאריך קבלה | התאריך שמתחת למספר המרכזי / בחותמת "התקבל" |
| גורם שולח | מושווה לרשימת שולחים מוכרים |

מספרים לא רלוונטיים – טלפון, פקס, כתובת, מיקוד, מחלקה, בית חולים, רישיון רופא – מסוננים ולא מוצגים.

### הגנות על הנתונים

- ערך שהלבורנטית מחקה **לא חוזר** בעיבוד חוזר; החלטות ידניות לא נדרסות.
- מספר התחייבות שמופיע בשני טפסים מסומן כ"כפול", עם השוואה ויזואלית של שני העמודים (התרעה בלבד, לא חסימה).
- שדה שלא נמצא נשאר "לא נמצא" עד שהלבורנטית מחליטה – טופס לא מאושר בשקט בלי שדה חובה.

## טכנולוגיות

- **צד שרת:** Python, FastAPI, SQLAlchemy + Alembic, OpenCV, Tesseract, zbar, Google Gemini
- **מסד נתונים:** SQLite בפיתוח, PostgreSQL (AWS RDS) בענן – כל הבדיקות רצות על שניהם
- **קבצים ותמונות:** תיקייה מקומית בפיתוח, באקט S3 פרטי בענן (`storage.py`) – לעולם לא בתוך מסד הנתונים
- **צד לקוח:** React 18, Vite, Tailwind CSS

## הרצה מקומית

דרישות: Python 3.11+, Node 18+, Tesseract (עם `heb`, `eng`, `osd`), zbar.

```bash
# צד שרת
cd backend
pip install -r requirements.txt
cp .env.example .env              # מפתחות Gemini; LLM_ENABLED=false כדי לעבוד בלי טוקנים
alembic upgrade head              # יצירת מסד הנתונים
python -m db.seed_senders         # טעינת רשימת השולחים
uvicorn main:app --port 8000

# צד לקוח (בטרמינל נוסף)
cd frontend
npm install
npm run dev                       # http://localhost:5173
```

בדיקות: `pytest` מתוך `backend/`. על PostgreSQL: `TEST_DATABASE_URL=postgresql+psycopg://user:pass@host:5432/db pytest`.

## הרצה בענן (AWS)

`backend/Dockerfile` ו-`frontend/Dockerfile` בונים את שתי התמונות. התשתית (EKS, RDS, S3, ECR) ב-[virology-lab-hackathon-infra](https://github.com/SaraVaisbord/virology-lab-hackathon-infra), והפריסה ב-[virology-lab-hackathon-k8s](https://github.com/SaraVaisbord/virology-lab-hackathon-k8s). הגדרות הענן (משתני סביבה): `DATABASE_URL`, `STORAGE_BACKEND=s3`, `S3_BUCKET`, `API_PREFIX=/api`.

פירוט נוסף על צד השרת: [`backend/README.md`](backend/README.md). תכנון המערכת: [`system_design.md`](system_design.md).

## מבנה

```
backend/
  api/                 נקודות קצה (העלאה, טפסים, אוצר מילים לממשק)
  db/                  מודלים, שאילתות, ו-constants.py – מקור אמת יחיד לשדות, תוויות וסטטוסים
  services/            תור עיבוד, חילוץ והצלבה, ייצוא
  preprocessing.py     עיבוד מקדים של עמוד
  local_extractor.py   OCR מקומי: תוויות → ערכים
  ai_extractor.py      Gemini (כולל מעבר אוטומטי בין מפתחות כשנגמרת מכסה)
  prompts/             ההנחיה ל-AI
frontend/src/          ממשק הלבורנטית
```
